# ワークログの規則を CLAUDE.md の外に置く方法を調べ、スキルの変更プランを作る

## 目的
`worklog-init` を入れると、`CLAUDE.md` に30行ほどの Worklog 節が足される。ユーザーはこれが気になっていて、`CLAUDE.md` 以外の置き場（rules など）の推奨を知りたい、スキルの変更プランがほしい、とのことだった。

## やったこと
前半は調査とプランの作成、後半はユーザーの了承を受けた実装。

### 調査とプラン

- スキルの管理場所を確かめた。`~/.claude/skills/worklog-init` はこのリポジトリの `skills/worklog-init` へのシンボリックリンクで、中の4ファイルはすべて Git で追跡され、`origin/main` にプッシュ済みだった。
- Claude Code の公式ドキュメントを、サブエージェント（claude-code-guide）に読ませて調べた。分かったこと:
  - `.claude/rules/*.md` は、`paths` の frontmatter が無ければ起動時に読み込まれ、`.claude/CLAUDE.md` と同じ優先度で扱われる。compact のあとも再注入される。サブフォルダも再帰的に読まれ、シンボリックリンクにも対応している（リポジトリの外を指すリンクは承認が要る）。
  - `CLAUDE.md` の `@path` インポートは本文を別ファイルに出せるが、`CLAUDE.md` に1行残る。読み込む量は減らない。
  - SessionStart の hook で文面を注入することもできるが、hooks のガイドは、毎セッションの注入には `CLAUDE.md` を使うよう勧めている。
  - プラグインは hook やスキルを配れるが、`CLAUDE.md` に当たる常時読み込みの指示は同梱できない。
  - `~/.claude/rules/` に置くとすべてのリポジトリに効き、リポジトリを選べない。
  - どこに置いても文面は強制ではなく、確実に守らせるには hook を使う、というのが公式の説明だった。今の2つの hook の役割と合っている。
  - Explore と Plan のサブエージェントは `CLAUDE.md` も rules も読まない。
  - `.claude/rules/` は Claude Code だけの仕組みで、`AGENTS.md` を読む他のツールには届かない。
- 変更プランをユーザーに示した。要点は、規則を `.claude/rules/worklog.md` に置き、`CLAUDE.md` には触れないようにすること。

ドキュメントの記述は、サブエージェントの報告で読んだもので、Claude 自身は原文を開いていない。

### 実装
- 素材 `assets/claude-md-section.md` を `assets/worklog-rule.md` に改名し、見出しを `# Worklog` にした。規則の文面は変えていない。
- `assets/worklog-check.py` の2つのメッセージを、`.claude/rules/worklog.md` を指す文に直した。
- `SKILL.md` を書き換えた。規則を `.claude/rules/worklog.md` にコピーし、`CLAUDE.md` には何も書かない。`CLAUDE.md` に素材と同じ内容の Worklog 節があれば削除し、内容が違えばユーザーに聞く。hook のスクリプトは素材で上書きする。
- このリポジトリを新方式にした。`.claude/rules/worklog.md` を素材へのシンボリックリンクにし、`CLAUDE.md` から Worklog 節を消した（消す前に、素材と同じ内容であることをスクリプトで確かめた）。

### 確かめたこと
- 直した hook は、今日のワークログが無いリポジトリで `git commit` を拒否し、新しい文面を出した。`git status` では何も出さなかった。
- 新しいセッション（`claude -p`、ツールなし）で、規則が読み込まれていた。このリポジトリ（シンボリックリンク）と、このリポジトリの下に作った仮のリポジトリ（コピー）の両方で確かめた。後者は、規則のファイルにだけ書いた合言葉を答えられた。
- 旧方式で導入済みの状態を再現した仮のリポジトリに、サブエージェントが `SKILL.md` だけを読んで適用した。手順7まで進み、`CLAUDE.md` からは Worklog 節だけが消え、他の内容は残った。
- サブエージェントが迷った箇所のうち4点を `SKILL.md` に反映した（更新時の全体像、既存の記録の「別の形式」の範囲、削除する節の範囲、今日のワークログがすでにある場合の hook の確かめ方）。

まだ確かめていないこと:
- スクラッチパッド（`/private/tmp` の下）に作った仮のリポジトリでは、規則が読み込まれなかった。そこではプロジェクトの `CLAUDE.md` も読み込まれていなかったので、規則の置き方ではなくフォルダ側の事情（信頼済みでないフォルダと推測）と見ているが、原因は突き止めていない。
- `/worklog-init` をスキルとして呼び出しての通し実行。試したのは、サブエージェントに手順書を読ませる形だけ。
- 反映した4点の修正のあとの `SKILL.md` は、もう一度は試していない。
- すでに旧方式で導入した他のリポジトリの移行。スキルをもう一度実行すれば移る作りにしたが、どのリポジトリが対象かは調べていない。

## 判断
- **置き場は `.claude/rules/worklog.md`（`paths` なし）にする（Claude の提案、ユーザーが了承）。** 常時読み込まれ、`CLAUDE.md` に1行も残らず、Git で配れる。今の「リポジトリごとの `.claude/` に置く」方針とも揃う。
- **プラグイン化と `~/.claude/rules/` は勧めない（Claude の判断）。** 前者は規則の文面を常時読み込ませる手段が hook しかなく、後者は入れるリポジトリを選べない。
- **`CLAUDE.md` には案内の1行も残さない（ユーザーの決定）。** Claude Code には不要。`AGENTS.md` を読む他のツールには規則が届かなくなることは、決める前に伝えた。
- **再実行すると旧方式から移行する作りにした（Claude の判断）。** 移行用の別の手順やスキルを作らずに済む。素材と同じ節だけを自動で消し、手が入った節は消さずに聞く。
- **hook のスクリプトは再実行のたびに素材で上書きする（Claude の判断）。** 古いスクリプトは `CLAUDE.md` の Worklog 節を指す文面のままなので、規則と一緒に更新する必要がある。
- **このリポジトリの規則はコピーではなくシンボリックリンクにした（Claude の判断）。** hook と同じ理由で、素材とのずれを防ぐ。`CLAUDE.md` にあった「同じ内容にしておく」という手作業の注意が要らなくなった。
- **サブエージェントの指摘のうち、節の比べ方の細部、設定が一部だけ違う場合、ワークログの時刻の食い違いは反映していない（Claude の判断）。** 実際に困った例がまだ無い。
- **実装の直後はコミットしなかった（Claude の判断）。** 頼まれていなかった。
- **`main` に直接コミットしてプッシュする（ユーザーの決定）。** ブランチを切らなかったのは Claude の判断で、前回ユーザーが `main` へのマージとプッシュ、作業ブランチの削除を続けて頼んでいたため。

> ここに記載した判断はその時点の状況に基づくものであり、恒久的な決定ではありません。
