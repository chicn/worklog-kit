# ワークログの運用を決め、worklog-init スキルを作る

## 目的
新しいリポジトリを作るたびに、そのプロジェクトでやったことをすべて記録するワークログのフォルダを用意したい。これまでは Claude が指示文を読んで自発的に書くだけで、書き忘れを検知する仕組みが無かった。運用を決め、導入用のスキルを作り、育てる場所としてこのリポジトリを立ち上げる。

## やったこと
- 既存の2つの運用を調べた。
  - ShareDoc（`docs/worklog/`、4日で43件）: 規則は `CLAUDE.md` の Worklog 節。見出しは 目的 / やったこと / 判断。
  - ivory-ai-lab（`worklog/`、3日で14件、うち7件は定期実行の記録）: 規則は `docs/worklog-rules.md`。見出しは 実施済み / 確認結果 / 未実施。
  - どちらも hooks は使っていなかった。グローバルの `~/.claude/settings.json` の hooks は通知音と Orca 連携だけだった。
- スキル `worklog-init` を作った（`skills/worklog-init/`）。
  - `SKILL.md`: 導入の手順（現状確認、フォルダ作成、`CLAUDE.md` への節の追加、hook の設置、動作確認、最初のワークログ）
  - `assets/claude-md-section.md`: `CLAUDE.md` に入れる Worklog 節
  - `assets/worklog-check.py`: 2つの hook の本体
  - `assets/settings-hooks.json`: `.claude/settings.json` に入れる hook 設定
- hook のスクリプトを仮のリポジトリで11通り試し、すべて期待どおりだった（コミットの拒否と通過、ワークログのフォルダが無い場合、壊れた入力、応答終了時の確認と再確認の抑止など）。
- スキルを `~/.claude/skills/worklog-init` からこのリポジトリに移し、元の場所にはシンボリックリンクを張った。
- このリポジトリ自身に仕組みを入れた（`docs/worklog/`、`CLAUDE.md`、`.claude/settings.json`、`.claude/hooks/worklog-check.py`）。
- 空だった `skills/SKILL.md` を削除した。

まだ確かめていないこと:
- 実際の Claude Code のセッションで2つの hook が発火するところ。確かめたのはスクリプトに入力を渡した場合の動作だけ。
- スキルを `/worklog-init` として通しで実行するところ。このリポジトリへの導入は、手順を手で進めた。

## 判断
- **中身は ShareDoc の形式にする（ユーザーの決定）。**
- **粒度は PR 粒度を基本に、同じ日の続きは追記、日をまたいだら新しいファイルにする（ユーザーの希望「PR と同じくらいの粒度か、日をまたがない粒度」を受けて Claude が提案）。** 2つの希望が両立し、ファイル名の日付と中身の日付が必ず一致する。hook も「今日の日付のファイルがあるか」を見るだけで済む。
- **コミットしない作業（調査や検討）も記録する（ユーザーの決定）。** このため、コミット時のチェックに加えて、応答終了時の確認を入れた。
- **フォルダは `docs/worklog/` にする（Claude の提案、ユーザーは未決だった）。** ShareDoc と揃い、`docs/adr/` と隣に並び、ルート直下が散らからない。
- **hooks はグローバルではなくリポジトリごとの `.claude/` に置く（Claude の提案）。** ユーザーは「まずスキルを作る」方針で、hooks の恩恵も試したいとのことだった。リポジトリごとなら、スキルだけで完結し、ワークツリーやチームメンバーにも効き、合わなければそのリポジトリから消せる。
- **セッション開始時の注入は入れない（Claude の判断）。** 規則は `CLAUDE.md` に書けば毎回読まれる。
- **応答終了時の確認は、ツールを10回使ったら1回だけ行う（Claude の判断）。** 毎回聞くとうるさいため。一区切りかどうかは Claude が判断する。10回という値は仮で、使いながら調整する。
- **slug は英小文字とハイフンにする（Claude の判断）。** ShareDoc に合わせた。
- **スクリプトは `python3` で書く（Claude の判断）。** セッション記録（JSONL）を読む必要があるため。失敗したら何もせず通す作りにした。
- **既存の作業記録が別の形式であるリポジトリでは、スキルは止まってユーザーに聞く（Claude の判断）。** ivory-ai-lab のような場合に、移すか残すかを勝手に決めないため。
- **プロジェクト名は `worklog-kit`（Claude が候補を出し、ユーザーが決定）。**
- **スキルの置き場は `skills/worklog-init/` にする（Claude の判断）。** 今後スキルが増えても並べられる。
- **このリポジトリの `.claude/hooks/worklog-check.py` はコピーではなくシンボリックリンクにする（Claude の判断）。** 素材と実際に動く hook がずれないようにするため。他のリポジトリではスキルの手順どおりコピーする。
- **このファイルの時刻は、この作業の会話を始めた 16:38（GMT）にした（Claude の判断）。**

> ここに記載した判断はその時点の状況に基づくものであり、恒久的な決定ではありません。
